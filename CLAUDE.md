# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal Nix flake that defines NixOS configurations for multiple physical/virtual machines and nix-darwin configurations for macOS machines, all sharing a common set of modules and a single home-manager profile. Configuration is deployed by running `nixos-rebuild`/`darwin-rebuild` directly on each target host against this flake — there is no CI/build server.

## Commands

```sh
# Update all flake inputs (writes flake.lock)
nix flake update

# Apply the configuration on the current host (run locally on that machine)
sudo nixos-rebuild switch --flake .
# or explicitly select a host defined in flake.nix
sudo nixos-rebuild switch --flake .#desktop

# macOS hosts (MacBook, MacBookProM1)
darwin-rebuild switch --flake .#MacBook

# Build without switching (useful to check a config evaluates/builds)
sudo nixos-rebuild build --flake .#<hostname>

# Format Nix files (alejandra is the project formatter, installed in configs/common.nix)
alejandra .

# Garbage collect / inspect generations
sudo nix-collect-garbage -d
sudo nix-env -p /nix/var/nix/profiles/system --list-generations
./scripts/trim-generations.sh <keep-gens> <keep-days> <profile>   # interactive, prompts before deleting

# Edit sops-encrypted secrets (files under secrets/)
sops secrets/secrets-<host>.yaml
```

Commits in this repo are conventionally made with `scripts/commit.sh`, which produces messages of the form `<hostname>-<date>-<time>` (e.g. `desktop-2026-08-23-11-13-42`) — see recent `git log` for the pattern. There are no automated tests or lint CI in this repo; correctness is checked by `nixos-rebuild build`/`switch` evaluating and activating successfully.

## Architecture

**flake.nix** is the entry point. It pins inputs (nixpkgs-unstable as the primary `nixpkgs`, nixos-hardware, impermanence, sops-nix, home-manager, nix-darwin, nix-index-database, chaotic (CachyOS) and kwin-effects-forceblur) and declares `nixosConfigurations` and `darwinConfigurations` for each host. Every `nixosConfiguration` follows the same shape: a list of upstream modules (impermanence, relevant nixos-hardware profiles, sops-nix, chaotic) plus one `./machine/<host>.nix` entry point, plus a home-manager module block that always imports the single shared `./configs/home.nix` as user `alex`'s home-manager profile.

**machine/** — one file (or directory with `configuration.nix` + `hardware-configuration.nix`, for hosts originally generated by the NixOS installer) per host: `desktop.nix`, `framework.nix`, `homeserver.nix`, `mini.nix`, `macbook.nix`, `vps-arm.nix`, `thinkpad/`, `nixos-vm/`, `nixos-vm-fusion.nix`, `nixos-virtualbox/`. Each machine file sets `networking.hostName`, `system.stateVersion`, hardware/boot/filesystem specifics, per-host `sops.secrets`, and imports whichever `configs/*.nix` modules and `configs/services/*.nix` service modules are relevant to that host (e.g. `vps-arm.nix` imports most of `configs/services/`, since it's the public-facing server; `desktop.nix` imports desktop/gaming-oriented modules like `configs/games.nix` and `configs/plasma-desktop.nix`).

**configs/** — shared, reusable NixOS modules imported selectively by the machine files: `common.nix`/`common-linux.nix` (base packages and SSH known hosts, shared across NixOS and Darwin vs. Linux-only), `user.nix`/`user-gui.nix` (the `alex` user account, hashed password via sops, authorized SSH keys), `filesystem.nix` (btrfs subvolume layout), `boot.nix`, `hardware.nix`, `docker.nix`, `libvirtd.nix`, `printing.nix`, `browser.nix`, `develop.nix`, `games.nix`, `plasma*.nix` (KDE variants), `borg.nix` (borgbackup jobs), `virtualbox.nix`. `configs/services/*.nix` are one-module-per-service definitions for things self-hosted on the homeserver/vps-arm hosts (nextcloud, immich, paperless, gitea, grafana, adguardhome, headscale, postgres, etc.) — add a new self-hosted service here, then import it from the specific machine file(s) that should run it.

**configs/home.nix** is the single home-manager profile shared by every host (NixOS and Darwin alike) — shell (zsh + oh-my-zsh + powerlevel10k, config in `configs/p10k-config/`), tmux, git, ssh client config with host aliases, and dotfiles pulled from `home/` (e.g. `home/bin/*` scripts symlinked into `~/.bin`). There is no per-host home-manager customization; anything host-specific belongs in the NixOS/Darwin module under `machine/`, not here. (`configs/home-manager/default.nix` is currently an empty stub, not wired into the flake.)

**secrets/** — sops-encrypted YAML, one file per host (`secrets-<host>.yaml`) plus a shared `secrets.yaml`, decrypted via age keys. `.sops.yaml` maps each host's age public key (and the `alex` user key) to which secret files it may decrypt — when adding a new host that needs secrets, add its age key there and create a matching `secrets-<host>.yaml`, then reference individual keys via `config.sops.secrets.<name>` in that host's machine file.

**overlays/default.nix** defines three overlays wired into hosts that opt in via `nixpkgs.overlays` (see `machine/nixos-vm/configuration.nix` for the pattern): `additions` (exposes `pkgs/` custom packages, currently `psensor`), `modifications` (ad hoc upstream package overrides), and `unstable-packages` (exposes the full nixpkgs-unstable set as `pkgs.unstable`, since the flake's primary `nixpkgs` is already unstable).

**pkgs/** — custom package derivations not in nixpkgs, wired in via the `additions` overlay; add new ones as `pkgs/<name>/default.nix` and register them in `pkgs/default.nix`.

**Persistence**: several hosts use `environment.persistence."/persist"` (from the impermanence module) to whitelist stateful paths that survive an otherwise ephemeral/wiped root — check a host's `environment.persistence` block before assuming a directory under `/var` or `/etc` persists across reboots.

**backup/** holds retired/unused modules (e.g. `pantheon.nix`, `user-baremetal.nix`) kept for reference — not imported by the flake.
